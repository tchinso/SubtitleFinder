# 애니 자막 찾기

한국어·일본어 애니메이션 자막을 찾고 공개 파일의 내용을 확인해 저장하는 웹 앱입니다. [sub.h2h.workers.dev](https://sub.h2h.workers.dev)에서 이용할 수 있습니다. 정적 화면과 검색·다운로드 API를 Cloudflare Worker 하나로 배포하며, 별도 외부 API 키는 필요하지 않습니다.

## 사용 방법

1. 한국어 제목으로 **애니시아 작품 찾기**를 누르고 정확한 작품·시즌을 선택합니다. 선택한 애니시아 작품의 정식 제목과 등록 제작자 정보를 기준으로 검색합니다. 시즌·회차를 비우면 전체 후보를 확인합니다.
2. 애니시아에서 작품을 찾지 못하면 **입력 제목으로 자막 찾기**를 사용합니다. 알고 있는 게시글, 공개 첨부파일 또는 **Google Drive 공유 폴더** 주소는 **링크 확인**에 넣습니다.
3. 일본어 자막은 **Jimaku 파일 찾기**로 실제 파일 목록을 확인합니다. 영문·로마자·일본어 원제를 사용할 수 있으며, 한국어 제목은 애니시아에서 원제가 하나로 확인되는 경우에만 연결합니다. 확인되지 않으면 영문·원제로 다시 검색하거나 Jimaku 원문을 엽니다. 이전에 선택한 파일과 유사한 배포본은 회차가 맞는 후보 안에서 우선 표시합니다.
4. 후보의 **내용 확인 · 저장**을 누르면 실제 형식, 문자 인코딩, 대사 수를 확인할 수 있습니다. **원본 저장**은 원래 바이트를 보존하고, **UTF-8 사본 저장**은 별도 파일을 만듭니다. ZIP은 내부 자막을 골라 확인·저장하고, 함께 제공된 폰트도 저장할 수 있습니다.
5. **저장 결과 대신 새로 검색**을 선택하면 검색 결과와 파일의 저장본을 건너뛰고 다시 요청합니다. 검색 결과는 브라우저 세션에서 5분간, 내려받은 파일은 해당 브라우저에 최대 20개까지 재사용합니다. 브라우저 저장 공간을 사용할 수 없어도 검색·다운로드는 동작합니다.

**빅파일·피디팝·OpenSubtitles·Google·Jimaku** 링크는 각 사이트의 검색 화면을 엽니다. 빅파일·피디팝은 사이트 로그인과 다운로드 프로그램이 필요할 수 있습니다. OpenSubtitles는 모든 언어를 검색하며, 로그인이나 브라우저 검증은 원문 사이트에서 직접 완료합니다.

## 검색·파일 처리 범위

- **제작자 주소 복구:** 등록 게시글이 사라졌을 때 애니시아 제작자 목록과 최근 자막 등록에서 이름이 정확히 같은 제작자의 다른 주소를 확인합니다. 네이버 검색에는 RSS·모바일 목록 보조 경로를 사용합니다.
- **보조 작품 목록:** 애니시아 검색을 분기별 작품·제작자 목록으로 보완합니다. 목록은 정적 스냅샷이므로 `worker/blog-directory-data.js`의 갱신일·출처를 유지하며 업데이트해야 합니다. 목록에 있다는 사실만으로 자막 일치를 확정하지 않습니다.
- **Drive 폴더:** 공개 폴더와 작품명이 맞는 하위 폴더에서 회차별 자막·압축파일과 폰트를 찾습니다. 관계없는 작품 이름은 제외하고, 제목을 확인할 수 없는 숫자 파일명은 검토 후보로 표시합니다.
- **회차 대응:** AniList에서 확인한 전작·후속작 관계와 실제 회차 수로 시즌 회차와 통산 회차 후보를 계산합니다. 회차 수를 임의로 13화 등으로 가정하지 않습니다.
- **인코딩·내용 검증:** SRT·VTT·ASS/SSA·SMI/SAMI의 시간 정보와 대사를 검사하며 UTF-8, UTF-16, 한국어·일본어 레거시 인코딩을 처리합니다. 확장자만 자막인 오류 페이지나 빈 파일은 저장하지 않습니다.
- **통합 자막 분리:** 파일명에 명시된 회차 범위와 충분한 대사·재생시간, 큰 타임스탬프 초기화가 모두 확인된 SRT·VTT·ASS에서만 회차 사본을 만듭니다. 불확실한 경우 원본을 유지합니다.
- **캐시:** Worker에서 동일 요청을 합치고 작품·게시글·파일 응답을 제한된 크기로 재사용합니다. 외부 사이트 갱신에 실패해 이전 검색 결과를 표시할 때는 안내를 붙입니다. 서버 캐시는 영구 저장소가 아닙니다.

공개 파일은 최대 6 MiB, 자막 본문은 최대 5 MiB까지 처리합니다. ZIP은 항목 수·전체 크기·개별 크기·무결성을 검사하며 암호화 ZIP 등 지원하지 않는 구조는 거부합니다. **웹의 7z·RAR는 원본 저장만 지원**합니다. 폰트는 파일로 저장하며 시스템에 설치하지 않습니다.

WinPNG·Jamaker처럼 이미지에 담긴 자막은 **원문 게시글의 뷰어에서 직접 확인**합니다. Worker에는 해당 뷰어를 실행할 브라우저가 없어 자동 추출하지 않습니다. 비공개 파일, 로그인·봇 검증, 사이트 자체 다운로드 제한은 우회하지 않습니다. 탐색 횟수 제한이나 원문 변경으로 일부 파일을 찾지 못할 수 있으므로 최종 작품·회차·배포본은 원문과 함께 확인해 주세요.

## 로컬 실행

Node.js 22 이상과 pnpm이 필요합니다.

```sh
pnpm install --frozen-lockfile
pnpm dev
```

Wrangler가 출력하는 로컬 주소를 브라우저에서 엽니다. `pnpm test:web`으로 Worker·화면·파일 처리 회귀 테스트를 실행합니다. 기존 Python 구현의 회귀 테스트는 `python -m unittest discover -s tests -v`입니다.

## Cloudflare Worker 배포

`wrangler.jsonc`의 Worker 이름은 **`sub`**입니다. 기존 Cloudflare Git 연동에서는 `main`에 반영하면 빌드·배포되므로 로컬 Wrangler 로그인이 필요하지 않습니다. 배포 후 [상태 API](https://sub.h2h.workers.dev/api/health)와 실제 검색·다운로드로 확인합니다.

직접 CLI로 배포할 때만 해당 Cloudflare 계정으로 인증한 뒤 실행합니다.

```sh
pnpm exec wrangler login
pnpm deploy
```

`wrangler.jsonc`가 `web/`의 정적 파일과 `worker/`의 `/api/*` 검색·파일 API를 함께 배포합니다. 기존 Windows EXE는 이 배포 경로에 포함되지 않습니다.

## 구성

| 경로 | 역할 |
| --- | --- |
| `web/` | 검색·파일 검사·저장 화면과 브라우저 캐시 |
| `worker/` | 애니시아·Jimaku·Bigfile 검색, Drive 탐색, 회차 대응, 파일·ZIP 검증 |
| `wrangler.jsonc` | Cloudflare Worker와 정적 파일 배포 설정 |
| `subfinder/`, `run.py` | 기존 Python/Tkinter 구현; 자막 내용·인코딩 검증 및 제한된 7-Zip 처리 |

웹 앱은 허용된 출처의 공개 페이지·첨부 주소만 요청하며, 다른 호스트로의 이동과 응답 크기를 제한합니다.
